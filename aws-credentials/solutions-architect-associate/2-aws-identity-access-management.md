# 1. Identity Access Management [`IAM`]

IAM은 Identity Access Management의 약자로 AWS 리소스에 대한 계층화된 권한을 관리하고 전반적인 액세스를 제어할 수 있는 서비스이다. 리소스를 사용하도록 인증 2FA, SAML SSO, TOTP 등 다양한 인증과 권한 부여 대상을 제어한다. 이는 인증 및 권한 부여를 제어하는 데 필요한 인프라를 제공한다.

#### ID

* AWS 계정을 생성하는 시점부터 모든 AWS 서비스와 리소스에 대한 액세스 권한이 있는 AWS 계정 루트 사용자의 단일 로그인 ID로 시작한다. 루트 사용자를 사용하지 않는 것을 원칙으로 하여 루트 사용자 자격 증명이 필요한 작업은 별도로 다른 ID로 설정하고 수행하는 데 필요한 리소스에 대한 액세스 권한을 제어할 수 있다.

#### 액세스 관리 [`Access Manage`]

* IAM에 설정된 사용자는 로그인 자격 증명을 사용하여 AWS에 인증하기 때문에 AWS 계정에서 신뢰하는 위탁자와 로그인 보안 인증 정보를 일치시키는 방식으로 인증이 제공된다. `위탁자`에게 리소스 액세스 권한을 부여하도록 요청이 이루어져 리소스에 대한 권한이 부여된 경우 권한 부여 요청에 대한 응답으로 액세스 권한이 부여된다.

* 서비스를 선택하면 인증 요청이 해당 서비스로 전송되어 인증된 사용자 목록에 ID가 포함되어 있는지 부여된 액세스 수준을 제어하기 위해 어떤 정책이 적용되고 있는지 확인한다. AWS 계정 내의 `위탁자`나 신뢰할 수 있는 AWS 계정을 통하여 인증을 요청할 수 있다.

> [!NOTE]
> * **위탁자**
>   * IAM 사용자
>   * AWS STS 페더레이션 위탁자
>   * IAM 역할 또는 애플리케이션

## 1.1 서비스 가용성

* IAM은 많은 AWS 서비스처럼 최종 일관성을 유지하며 데이터 센터 내의 여러 서버로 데이터를 복제함으로써 고가용성을 추구한다.
* 일부 데이터를 변경 요청이 성공하면 변경이 진행된 후 저장되고 변경 사항은 IAM 전체에 복제되어야 하고 이는 일정 시간 이상의 소요가 발생한다.
* 변경 사항에는 사용자, 그룹, 역할 또는 정책을 만들거나 업데이트한 것이 포함되어 변경 사항을 애플리케이션의 중요한 고가용성 코드 경로에 포함시키지 않는 것을 권장한다.
* 비활성화 상태의 초기화 루틴이나 설정 루틴에서 IAM을 변경하고 프로덕션 워크플로우에서 변경 사항을 적용하기 전에 변경 사항이 배포되었는지 확인해야한다.

### 1.1.1 서비스 비용 정보 [`Service Cost Information`]

* `AWS Identity and Access Mangement`, `AWS IAM Identity Center`, `AWS Securty Token Service`는 추가 비용 없이 제공되는 기능이다. 
* IAM 사용자 또는 AWS STS 임시 보안 자격 증명을 사용하여 다른 AWS 서비스에 액세스하는 경우에만 요금이 부과된다.
* `IAM Access Analyzer` 외부 액세스 분석은 추가 비용 없이 제공되만, 비활성화 액세스 분석 및 고객 정책 확인에는 요금이 발생한다.

> [!NOTE]
> * **AWS Security Token Service (`AWS STS`)**
> * **AWS IAM Identity Center**
>   * AWS 애플리케이션에 대한 인력 액세스 관리에 권장되는 서비스이다. 기존 ID 소스를 한 번 연결하여 사용자들에게 AWS 애플리케이션에 대해 공통된 관점을 제공하는 데 사용할 수 있는 솔루션이다.
>   * 사용자들은 AWS 애플리케이션 전반에서 간소화되고 일관된 경험을 할 수 있으며, 기존 AWS 계정 액세스 구성과 함께 작동한다.
> * **IAM Access Analyzer**
>   * 최소 권한은 요구 사항의 변화에 따라 적절하게 세분화된 권한을 부여하여 지속적인 목표를 달성할 수 있다.
>   * 권한을 설정, 확인, 조정할 수 있는 기능을 제공하여 최소 권한을 사용하도록 안내한다.

# 2. IAM 접근 권한 타입 [`IAM Access Authority Type`]

* IAM은 AWS 신원 및 접근 관리는 권한을 안전하게 관리할 수 있게 해주는 도구이다. AWS 리소스 IAM 사용의 주요 장점 중 하나인 하나는 공유 할당이 가능하기 때문에, 계정에 대한 접근 권한 또한 세세한 권한을 할당하여 미래의 사용자가 어떤 행동을 다룰지 정확히 제어할 수 있는 부분이다.
* 사용자는 특정 자원에서 공연할 수 있으며 이러한 수준의 접근 통제는 매우 중요하기 때문에 AWS 환경의 고수준 보안을 유지하는 것이 목표이며 여러 보안 기능을 제공한다.

> [!NOTE]
> * **다중 인증 (MFA)**
>   * Virtual MFA Device
>   * Universal 2nd Factor Security Key
>   * Hardware Key Fob MFA Device
>   * Hardware Key Fob MFA Device for AWS GovCloud (US)
> * Identity 페더레이션 신원 제공자
> * AWS CloudTrail

## 2.1 AWS 계정에 대한 공유 접근 권한 특징

#### 세분화된 권한

서로 다른 자원에 대해 다른 사람에게 권한을 부여할 수 있다. 일부 사용자에게 `Elastic Cloud Computing`, `Simple Storage Service`,`S3`, `DynamoDB`, `Reshift` 및 기타 AWS 서비스에 대한 완전한 접근 권한을 허용할 수 있으며 추가로 별도의 사용자에게 특정 부분만 허용하거나 모든 권한을 부여할 수 있지만 S3 버킷에 대한 읽기 전용 접근이나 관리 권한 EC2 인스턴스에 청구 접근만 가능하지만 이후 어떠한 행동을 취할 수는 없다.

#### 애플리케이션에 대한 AWS 리소스 보안 접근

IAM 기능을 사용해 실행되는 애플리케이션에 대해 안전하게 자격 증명을 제공할 수 있고, EC2 인스턴스에서 사용된다. 이 자격 증명들은 애플리케이션이 접근할 수 있도록 기타 AWS 접근에 대한 권한을 부여한다.

#### 다중 인증 [MFA]

계정에 2단계 인증을 추가와 개별 사용자에게도 별도의 추가 인증 수단을 적용할 수 있다. MFA에서는 사용자들이 비밀번호나 접근 권한만 제공하는 것이 아니라 계정과 함께 작동할 수 있는 키와 함께 특별히 설정된 기기에서 나오는 일련번호 형태의 코드도 필요하다. 기존에 다른 서비스와 `FIDO` 보안 키를 사용하고 있고 AWS 포함하여 지원하여 구성에 대해 WebAuthn을 MFA 보안을 사용할 수 있다.

#### 정체성 연합

이미 다른 곳에서 비밀번호를 가지고 있는 사용자를 허용할 수 잇으며, 접근권한 AWS 계정과 IAM 기준에 가장 적합한 임시 자격 증명을 부여하여 신원 연합을 사용하면 AWS의 보안을 강화할 수 있다.

#### 보증을 위한 신원 정보

사용자의 자원 요청에 관한 정보를 포함한 기록 계좌 로그를 받고 IAM 신원을 기반으로 한다.

## 2.1 PCI DSS 준수

IAM은 처리, 저장, 전송을 지원해 서비스 제공자에 의해 신용카드 데이터에 대한 정보와 결제 산업(PCI) 데이터 보안 표준(DSS)을 준수하는 것으로 검증되었다.

# 3. IAM은 언제 사용하는 것이 적합한가?

* IAM의 신원 및 접근 관리는 출입 제어의 기반을 제공하는 핵심 인프라 서비스이다. AWS내 신원을 기반으로 하여 계정에 접근 시도할 때마다 IAM을 사용하기 때문에 어떻게 사용하느냐에 따라 구체적인 책임과 업무 기능이 달라진다. 
* IAM통해 AWS 리소스에 접근하여 관리자가 적절한 권한을 부여하는 업무를 진행하며 역할과 상관없이 인증할 때마다 상호작용하게 되면서 AWS 리소스에 대한 접근 권한을 부여한다. 이는 사용자로 로그인 하는 것도 포함된다.
* 정책과 권한 생성에 있어 유연하고 세밀한 접근법을 요구하며 어떤 주체가 할 수 있는지 통제할 수있도록 신뢰 정책을 정의할 수 있다.
* 행동과 장원을 명시하는 식별 기반 정책 외에 역할 수행하고 이러한 IAM 정책을 설정함으로써 사용자가 그리고 애플리케이션은 필요한 작업을 수행할 수 잇는 적절한 권한 수준을 가지고 있다.

## 3.1 다양한 업무를 수행

IAM 사용 방식은 AWS에서 하는 작업에 따라 다르다.
* **서비스 사용자**
  * AWS 서비스를 사용해 업무를 수행한다면, 관리자가 적절한 자격 증명과 권한을 제공한다. 확장된 업무를 수행을 하고자 하면 추가 권한이 필요할 수 있으며 접근성 관리는 관리자에게 올바른 권한을 요청하는데 도움을 줄 수 있다.
* **서비스 관리자**
  * 회사에서 AWS 리소스를 담당하고 있다면, IAM에서 완전히 접근할 수 있지만 IAM에서 어떤 권한을 부여해야 서비스 이용자가 접근할 수 있는지에 대한 요청을 제출해야 한다. 관리자가 서비스 사용자의 권한을 변경할 수 있고 정보를 바탕으로 검토해야 한다.
* **IAM 관리자**
  * IAM 접근 관리 위한 정책을 작성하고 신원을 관리한다.

#### AWS 리소스에 접근할 권한이 부여

* 인증은 신원 증명을 사용해 AWS에 로그인하는 방법으로 AWS 계정 루트 사용, IAM 사용자 또는 IAM 역할을 수행하여 인증 받아야한다.
* `AWS IAM Identity Center`, `Single Sign-On (SSO)`, `Flatform Credential` 등 신원 소스 출처의 자격 증명을 통해 연합 신원으로 로그인할 수 있다.
* 프로그래밍 접근을 위해 AWS는 요청을 암호화 서명할 수 있는 SDK와 CLI를 제공한다.

#### IAM 사용자로 로그인

IAM 사용자는 특정 개인이나 애플리케이션에 대한 특정 권한을 가진 신원이다. 장기 인증 정보를 가진 IAM 사용자 대신 임시 자격 증명(`페더레이션`)을 사용하는 것을 AWS에서는 적극 권장한다.

#### IAM 역할 이행

IAM 역할은 임시 자격 증명을 제공하는 특정 권한을 가진 신원이며, 사용자는 사용자에서 IAM 역할으로 전환하거나 SDK 통해 API를 호출하거나 CLI로 역할을 수행할 수 있다.

#### 정책과 권한을 생성

사용자에게 권한을 부여하려면 정책을 생성하는데 이 정책은 사용자가 수행할 수 있는 범위와 행동에 대한 영향을 미칠 수 있는 자원이다. 어떤 행동이나 명시적으로 허용되지 않은 자원은 기본적으로 요청이 거부되며 정책은 생성될 수 있으며 별도의 주체에 적용할 수 있다.

IAM 역할과 함께 다음 정책을 사용할 수 있다.
* **신탁 정책**
  * 어떤 소유자가 조건에서 역할을 맡을 수 있는지 정의하고, 신탁 정책은 IAM 역할에 대한 특정 유형의 리소스 기반 정책이나 역할은 단 하나의 신뢰만 가질 수 있다.
* **신원 기반 정책 (`인라인 및 관리형 정책`)**
  * 역할 사용자가 수행할 수 있는 권한을 정의한다.
